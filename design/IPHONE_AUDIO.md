# v25 · iPhone 静音模式与网页音效

用户真机反馈：iPhone 的游戏声音开关已开启、媒体音量不为零，但开启手机静音模式后网页音效消失，其他 App 的视频仍有声音。

## 原因与依据

现有音效均通过 Web Audio API 的 AudioContext 输出，包含点按合成音、实录零钱和已选 E 过关音乐。WebKit 默认将其当作 ambient 音频，受 iPhone Ring/Silent 开关控制。HTML 音视频采用的媒体播放模式通常不受该开关控制。

- [WebKit 开发者对默认分类及静音开关差异的说明](https://bugs.webkit.org/show_bug.cgi?id=252746#c2)
- [MDN：AudioSession.type](https://developer.mozilla.org/en-US/docs/Web/API/AudioSession/type)

## 本版处理

在原有用户手势激活路径中、创建 / 恢复 AudioContext 前，功能检测 `navigator.audioSession`，可用时请求 `type = 'playback'`。不按设备或浏览器名称强行判断，不在页面载入时请求播放模式。

已有模式只保存一次；重复音效不反复切换。游戏静音、音量为零、页面隐藏或离开时，先停止音源并暂停 Context，再恢复此前模式。如果宿主已改为其他模式，不覆盖宿主的新值。音频设备初始化失败也释放请求的模式。

不改变音效素材、82% 默认音量、混音 / 限幅、重复触发去重或游戏数据。不创建静音循环、不增加后台播放音轨、不请求麦克风权限、不自动把手机媒体音量调高。仍需要页面内用户操作才能激活声音。

## 实际限制

Audio Session API 的可用范围有限。接口缺失、读取或设置被拒绝、宿主忽略写入时，继续原来的 Web Audio 路径，不阻塞游戏。微信 WKWebView 的实际会话也可能受微信宿主控制，不能只凭设置成功认定扬声器一定有声。

媒体播放模式可能暂停其他非混播媒体；这是系统播放类别的行为。关闭游戏声音或离开页面会释放本次请求的类别，但不能保证替其他 App 自动恢复音乐。游戏静音和音量为零始终优先于播放类别请求。

## 验证

`audio-session-tests.mjs` 覆盖：载入 / 关闭声音时不请求、创建 AudioContext 之前请求播放模式、重复提示不重复切类别、静音 / 音量零 / 后台释放、前台再次点击重新请求、保存原模式、保留宿主后续变更、接口缺失 / 抛错 / 忽略写入、音频 API 缺失和设备初始化失败。原音频测试继续覆盖素材、音量、停止、后台和重复触发。

当前环境缺少 Sites 指定的浏览器入口，也没有真实 iPhone，无法复现硬件静音开关。待用户分别用微信与 Safari 实测：手机静音、媒体音量非零，刷新页面后操作一次，再试听点按 / 零钱 / 过关；切后台再返回，点击后重试；最后关闭游戏声音验证完全静音。
