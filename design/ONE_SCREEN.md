# v24 一屏试玩

目标：手机主玩法无需上下滑动，保留可读字号、标准会计列报与完整剧情。首发仍是微信内网页，兼容 iPad、手机浏览器及电脑。交易引擎、随机条件、存档结构和声音素材不变。

## 画面与操作

- 页头只保留品牌、红色待填账本入口及菜单。现金、原料可做杯数和今日净利润为紧凑状态栏；五段进度缩成短条。
- 窄屏上下分区：摊位 / 动物场景、时钟与当前事件、任务面板、固定操作区。较宽平板与电脑把场景和任务放在左右两侧，依旧限定可视高度。
- 一段剧情按短对话推进，可以回看上一句；页码不是倒计时。最后一段才显示实际经营动作，阅读翻页不调用财务动作、不更改 revision、不发生成交。
- 答题时题干及必要数字常驻，字号不随屏幕缩小。较矮手机收起插画。作答后用讲解替换选项；错误解释延续醒目的红色反馈，每段内容都能翻到，不靠滑到题目底部寻找。
- 预算、记事、声音、名词、清算进入菜单或就近入口。预算不在借款场景重复铺满。时间入口只展示已处理和正在发生的事件，没有未来客人或未揭晓结果。

## 账本

三张报表共用固定大小的全屏浮层。标题、页签、报表翻页区、提示及核对按钮保持位置；内容依实际可视高度按完整行分组，按钮翻页。资产负债表继续左资产、右负债和所有者权益，两侧合计一起出现在最后一页。现金流量表保留经营 / 投资 / 筹资分组和现金核对，利润表保留规范层次。

分页仅切换真实行的 hidden 状态，不克隆输入框、不重新生成金额草稿。漏填 / 错误定位先显示对应页，再聚焦原空格。键盘 / 旋转重新分组时尽量跟随当前输入项，表单、焦点及交易保持。两次金额错误后的算法可原位展开；空间不足时收成“分步看看怎么算”，完整讲解另页显示。说明、概念帮助、交易来处另开分页阅读。名词词典等参考窗口仍可内部滚动，主场景不滚动。

## 实现

- `screen.css` 最后加载，覆盖原网页布局；body 高度由 visualViewport 驱动，含刘海和底部安全区，不禁用浏览器双指缩放。
- `screen.js` 组织剧情内容，按语义段落与实际空间分组，保留完整文本、选择和操作节点。分页游标只属于展示，切换场景不写入新交易。ResizeObserver、窗口 / visualViewport 变化及字体加载后重新排版。
- `sheet-pager.js` 根据真实报表结构分组；资产负债表同时分页左右两边，更新空现金流分组的可见性。保留实际输入对象，提供定位及详情阅读。
- 页面切换、关闭及后台返回仍沿用 platform.js、原存档和时钟暂停规则。菜单和辅助阅读也会暂停自然走时。

## 自动验证与边界

`npm test` 包含原有开张、历史赊账、回退、清算、声音、三表与设备兼容检查。旧 DOM 测试通过 `screen-test-helpers.mjs` 先翻到目标可见页再操作，避免直接点击隐藏经营动作。

新增 `npm run test:screen`：在 320×568、390×844、768×1024、1440×900 四种视口配置下走完开张篇，验证剧情翻页不改状态、完整文本保留、每个待填金额都可经报表页到达、输入节点在翻页和键盘尺寸变化中保持、题干常驻、解释替换选项、两错帮助和清算二次确认。这里是 DOM / 逻辑测试；容量的后备估算不能代替真实浏览器几何测量。

当前环境没有 Sites 指定的 cua_repl.js 浏览器入口，按工作流跳过浏览器预览，不启动替代浏览器。微信、Safari / iPad、Chrome 真机布局和音效验收待试玩。

## 真机优先路线

1. 手机竖屏从热下午的开摊念头开始，预算、零花钱、借款、设备、备货到第一笔销售，全程不拖动主页面。
2. 回看上一句、打开预算、展开时间记事后继续，核对经营没有提前发生，未来客人没有被预告。
3. 填报表时漏一处、填错两次，再收起 / 弹出键盘，确认待填页、算法说明与主按钮均可到达，三表不会忽高忽低。
4. 切到 iPad 横 / 竖屏和分屏，保留半填草稿；电脑缩放窗口，继续操作同一笔账。
5. 打烊保留小摊后应有现金 64、设备 16、借款 32、净利润 36 元；主动清算仍先二次提醒，最终现金 44、借款 0、净利润 32 元。

真机尚未通过验收，不在发布说明中声称已通过具体设备。

## v31 可读性与键盘内纠错

- 开摊预算不按条目拆页。零花钱 12 元、计划缺口 32 元各占一行；预算卡片缩减留白，较矮手机临时收起场景插画，菜单里的同一张预算也完整显示。
- 关闭待填账本后的草稿说明仅首次显示，以本局暂停次数保存；之后仍可从同一个继续入口回到账本。
- 点击报表名时，直接显示该表第一处待填 / 待改金额所在的页，不必从第一页寻找。定位不主动唤起键盘；重排时优先保留正在编辑的金额格。
- 错误金额格旁始终有“提示”按钮，可主动查看本局算法；连续两错后的原位算法仍保留。键盘打开时收起较长的原位文字，保留格旁按钮。核对失败若仍在同页，只更新提示和分页，不销毁金额输入节点；修正、草稿和实际交易分开保存。
- `screen-tests.mjs` 在四种视口配置下增加预算同页、重复提醒消失、短视口表名定位待填，以及键盘打开后的错误按钮与输入节点保留检查。DOM 无法证明真机实际几何布局与点按舒适度。

## v32 主面板宽度与记账事实

手机版将 `.game-layout` 从网格改为纵向 flex 时，继承了早期的 `align-items: start`；`.play-area` 的宽度仍是 auto，因而随最长文字计算宽度。首次收款把较长的备货说明换成较短的成交说明，触发主面板收窄。现在一屏主容器明确使用 stretch，主面板宽度为可用宽度的 100%。检查了 320、390、650、700、768、1024、1440 宽度下实际样式表的规则优先级，并运行营业和一屏导航检查；这些检查不代替手机实际几何测量。

`book-context.js` 从待填账本对应的已发生交易生成短摘要，不从清算的下一步取数字。设备出售显示账面价值、收款与处置损失；采购显示购入、实付、未付和报损；销售显示杯数、单价、实收、未收和材料成本；借还款与计提费用分别显示实际金额。适用时补充交易前现金，便于核对余额。摘要不随填入金额改变，也不记入新的交易。

摘要位于账本上方、分页区之外，允许自然换行，键盘与短视口布局不再隐藏它。键盘打开时压缩页脚留白和重复表头，为摘要与当前金额格留出空间。复杂的合并清算提供收付、损失汇总，完整流水仍在“说明与交易”中。`management-tests.mjs` 验证真实设备清算的数值与读取无副作用；DOM 检查覆盖三步 / 六步清算、切换报表、键盘打开后的摘要与草稿保留。
