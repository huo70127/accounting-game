# v26 · 独立手写金额试验

用户要求保留目前键盘输入，另做小试验，验证不用系统键盘就能手写金额、切到下一格以及撤销、删除、修改的体验。

## 入口与边界

- 正式游戏仍是 `/`，文件与 v25 完全相同。
- 新试验入口 `/handwriting.html`，不加入默认游戏流程，也不修改正式账本输入方式。
- 两个金额格分别是自己的零花钱和借来的钱。没有标准答案，不做会计判断或成绩记录。
- 试验只在内存里保留两份独立草稿；刷新清空试写。读取原音效偏好，复用声音与角色素材，但不写正式游戏存档或修改音效偏好。

## 交互

1. 点金额格，当前格高亮。用手指、触控笔或鼠标在下方纸面写完整金额。
2. 短暂停笔后识别，金额原位显示，旁边有最多三个候选。候选由笔迹得出，不依据金额格名称或游戏正确答案推断。
3. 点下一格会保留笔迹与识别结果；“记下这笔，下一格”明确确认当前金额。两格写完仍能点回任意格修改。
4. 撤销一笔与重做保留最多 40 步；清空当前格也能撤销。删末位删除最右侧整个字形，包括该字形的多笔。
5. “修改金额”提供页面内数字、负号、小数点、删末位和清空按钮。可修改识别结果，不需要系统键盘。改好的金额继续手写时，会用新笔迹替换，并可撤销回去。

没有 input、textarea 或 contenteditable。画布使用 Pointer Events、指针捕获和同一笔的合并采样；忽略额外指针，取消的笔迹不提交。横竖屏 / 可视尺寸变化时以同一比例重新显示笔迹。小屏缩掉引导与页脚，把面积让给书写。

## 本地识别

- 使用 MNIST 的 60,000 个训练样本训练 784 → 96 → 10 的小型网络。305,320 字节 Float32 权重随页面部署，JavaScript 直接推理，不引入外部推理运行时。
- 原始笔划先按横向位置分组，再标准化为 28×28。小数点、开头的负号按几何位置处理，多位数字按从左到右合并；显示三组候选。需要数字间留少量空隙，暂不支持叠写和数字连写。
- 推理代码只接收笔迹、模型和用户选定的候选，不接收字段名称或正确答案。笔迹不上传，也没有识别服务密钥。
- 网络获取的是固定的模型元数据和权重。首次加载未完成时仍能落笔；失败保留笔迹，可重试或使用页面内数字按钮。
- 每格有版本号与识别任务标识。撤销、清空、手改和切换期间，过期结果不能覆盖新草稿；正在等待的“下一格”也不能在输入已改动后突然推进。

模型在 MNIST 10,000 个独立留出样本上准确率 97.56%。此成绩只说明模型分类，不能代表手机手指书写、多位数分割、触控笔与小数点的真实识别率，发布说明不以此承诺体验。

模型权重及 `design/handwriting-model-fixtures.json` 的归一化留出图像按 MNIST 来源的 CC BY-SA 3.0 提供。署名、来源与限制在 `dist/handwriting/credits.txt`；正式游戏的其他资源原有归属不变。

## 验证

`npm run test:handwriting` 验证：

- 30 个归一化留出样本的 JavaScript 推理与 Python 模型一致。
- 标准 0–9 矢量笔迹，以及三个缩放下的 12、32、2.50、−16、0、0.5、−2.50；测试图形不代表所有人的实际笔迹。
- 候选覆盖、单笔撤销 / 重做、清空恢复、删除完整末位、两格互不影响、数值格式与页内修改。
- 使用真实本地模型的 DOM / 指针流程，含合并采样为空时的兼容、笔迹取消、尺寸变化、模型失败后重试、等待识别时清空以及旧下一步失效。
- 全页无系统文字输入节点，网络只读模型资源，不上传笔迹，不写原游戏存储。

原游戏的整套自动检查继续通过。当前没有 Sites 指定的浏览器入口，未运行替代浏览器，也没有完成真实几何布局或 iPhone / 微信 / Apple Pencil 实测。

## 用户试玩建议

先写 12 和 32，回到第一格撤销一笔、删末位和重写，再试候选与金额修改。随后试 2.50 和 −16，看看点、横线、1 / 7、3 / 8 是否容易看错。分别使用 iPhone 微信手指与 iPad 触控笔；重点评估书写面积、修改步骤和连续填写是否比键盘顺手，再决定是否接入正式账本。
