# v33 首发设备范围与验收

## 发布范围

| 入口 | 设备 / 浏览器 | 首发关注 |
| --- | --- | --- |
| 微信内网页（首发验收重点） | 当前主流 iPhone 微信、安卓微信 | 直接打开、触摸、软键盘、返回页面、音效 |
| iPad | Safari；横屏、竖屏、分屏 | 阅读宽度、左右资产负债表、旋转与浮动 / 硬件键盘 |
| 手机网页 | iPhone Safari、安卓主流浏览器 | 320px 起的窄屏、地址栏变化、刘海 / 底部安全区 |
| 电脑网页 | Chrome、Edge、Safari | 鼠标、键盘、窗口缩放、三表切换 |

沿用纯静态网页、原网址、同一财务与剧情模型。进度保存在当前设备的当前浏览器，微信和 Safari 的本地存档彼此独立；不增加账号、云端或跨设备同步。旧进度照常迁移。

目标是当前主流浏览器，按实际功能补兼容，不以用户代理字符串区分金融规则。补原生 dialog、JSON 状态克隆与数组 at 的缺失能力，不承诺所有历史内核都支持现有 ES modules、BigInt 和现代语法。

## 布局

- 窄手机使用紧凑页头和单列场景，工具按钮拥有更大点击范围，账本待填标记仍可见。
- 小屏把搭档与摊位放在上方，任务放在下方；较宽平板和电脑左右分区。主页面固定一屏，剧情与长表由按钮翻页。
- 报表扩展到合适宽度，平板文字增大；资产负债表始终左右分栏，利润表与现金流量表保留层次及同一金额列。
- 主操作栏固定，横屏短屏使用更紧凑的操作栏；刘海、底部手势区不覆盖内容。
- 小问号保持 12px 视觉，只增加透明点击范围。金额框维持简洁外观，外层有更大点击区域，字号至少 16px。

## 键盘与可视区域

`platform.js` 优先读取 visualViewport，缺失时使用窗口尺寸，跟踪宽度、高度和垂直偏移。弹窗在实际可见范围内定位，不只依赖 dvh。软键盘或短屏幕出现时，标题、页签、提示及操作区域缩紧；中间账目按照剩余高度重新分页。配方采购也使用固定标题、合计与付款按钮，五种原料按可用高度翻页；键盘打开时收起说明和付款方式区，优先保留当前输入行。极短屏尽量保留一行输入与主操作，并提供收起键盘入口。

旋转或键盘尺寸变化仅更新 CSS 变量、布局类及可见行分组，不重建表单、不改金额、不触发核对。聚焦金额项时显示对应报表页，避免把整个页面拉走。用户双指缩放时保留浏览器缩放，不按放大后的视口强行重新排版。iPad 浮动键盘可能不改变 visualViewport；触屏设备在金额输入聚焦时仍提供“收起键盘”。

## 模态兼容

支持原生 dialog 时继续使用原生行为。缺失时增加遮罩、open 状态、层叠顺序、背景点击隔离、Tab / Shift-Tab 焦点循环、Escape 取消及关闭后的焦点返回。取消事件仍走原有草稿保留路径。JS 同步 modal-open 类，避免只依赖 CSS :has 隐藏主页面操作栏。

## 返回、声音与保存

visibilitychange / pagehide 时保存并停止空闲时钟、停止声音；pageshow / 返回前台时刷新可视区域并从当前分钟重新推进。不会补算后台时间或重抽客人条件，已有弹窗、问题和草稿继续保留。声音只在后续用户操作中恢复，增加 touchstart 激活作为 pointerdown 的补充，不要求微信 JS SDK，也不自动补播完成音。

## 自动检查

- `platform-tests.mjs`：320×568、390×844、412×915、768×1024、820×1180、1024×768、507×768、1440×900 的视口计算，键盘、旋转、缩放、字段内部滚动，原生与兼容弹窗、焦点循环，以及纯 JSON 状态克隆。
- `opening-dom-tests.mjs devices`：整局开张、iPad 横竖尺寸和键盘变化时精确保留表单节点、焦点、金额、版本与财务事实。
- `opening-dom-tests.mjs fallback`：无原生 showModal / close 时完整游玩、首次揭晓、名词、填表、草稿、清算和重玩。
- `opening-dom-tests.mjs clock`：弹窗 / 后台暂停，页面离开后取消计时、返回恢复且不重新生成交易。
- `screen-tests.mjs`：320×568、390×844、768×1024、1440×900 的一屏导航，故事 / 答题 / 报表的可见页操作、所有空格可达、金额节点与键盘焦点保留、提示和清算确认。
- `audio-session-tests.mjs`：手势请求媒体播放模式、关闭声音 / 音量归零 / 后台释放、重新激活、原模式保留，以及接口缺失、拒绝写入、无音频设备的兼容。不能代替 iPhone 静音键实测。
- `four-week-dom-tests.mjs`：稳健、扩张、补救、失败及缺失原生弹窗的四周逐日全流程；五种配方材料逐项采购、采购草稿保留、超支拦截、350px 键盘可视高度下输入节点与焦点保留、当前错误优先核对、漏填温和定位；24 个计划出摊日（第三周有 3 个雨天停摊）和 4 个盘账日依次可达，日常报表无须再输入金额但保留新行与变动动画。
- `management-dom-tests.mjs`：原料杯数打开存货、今日净利润默认打开利润表；320×568 与 390×844 下当前清算标题 / 操作 / 记账一致、空步骤切换、六点闭合图及剩余债务。DOM 检查不测量真实布局。
- `trading-tests.mjs` / `trading-dom-tests.mjs`：显著的天数 / 时间、前台营业时钟、逐批销量与收款、当前按钮版本、先小票后报表、暂停 / 后台 / 刷新继续、快进及减少动画；不测量真实布局和声音听感。
- 原有账目、随机条件、回退、旧档、三表与音频检查继续运行。

当前托管环境虽然有 Chromium，但缺少 Sites 工作流要求的 cua_repl.js 浏览器入口。按该工作流不启动替代预览或浏览器控制；上述为 DOM / 逻辑检查，尚未完成真实几何布局或各浏览器引擎验收。

## 真机验收路线（待实测）

1. 在各入口打开网址，确认不滑动主页面也能从自己的零花钱、父母借款玩到第一笔销售。图片、报表揭晓和首个手势后的音效可用。
2. 金额输入时弹出键盘，故意漏填、填错、连续填错，再正确填写。空格、提示和核对按钮可见、可达，漏填仍为温和引导。
3. 填一半旋转屏幕 / 切换 iPad 分屏，关闭账本再打开。金额及位置合理保留；三张表切换保持同一浮层和主按钮位置。
4. iPad 分别用全尺寸、浮动及硬件键盘；窄手机横屏也能收起键盘、查看账目和继续。
5. 开着账本 / 空闲营业时切后台，或离开页面再返回。草稿和当前事件保留，时钟未补走，没有迟来的庆祝音。
6. iPhone 打开硬件静音 / 静音模式、保持媒体音量非零，在游戏里开启声音并点击试听。分别用微信与 Safari 测试点按、零钱、过关声；切后台再回来，首次点击后可继续发声。关闭游戏音效后始终静音。
7. 打开采购单，分别调整柠檬、茶叶、糖浆、塑料杯与吸管；关掉后重开保留数量。键盘弹出、旋转与翻页时能看清当前原料、合计和确认按钮；确认前不扣钱。
8. 从第 1 周玩到第 4 周，检查已发生事件与当前事件、合同日期、报损、付款和回款；完成保留小摊或二次确认清算。查看三张表，再刷新 / 重新从同一浏览器入口打开，确认本地进度。

验收结果应记录实际设备、系统、微信 / 浏览器版本、横竖方向和问题截图。当前状态为“自动检查完成、真机待验收”，不标记任何实际设备已通过。

第三周验收：连续三天清楚显示停摊、0 杯和 0 元，不播放卖茶收钱动画；雨停后能看见隔离柠檬，周末只出现一笔整数报损。普通周有料直接开摊，不要求每天重买，也不应每日新增报损。
