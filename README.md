# 手打柠檬茶 · 八周暑假经营

当前 v37：从空钱盒开张，逐日经营完整八周。第五周可与会做点心的朋友合伙，第六周为稳定营业和休息时间决定是否请人代班，第七周参加夜市，第八周完成借款、报表和个人分配，选择保留摊位或清算退出。前三周的现制配方、周采购和一次暴雨报损保留，日常营业仍有收钱、销量、时钟和自动记账反馈。

本次试玩在账本底部提供临时“测试 · 一键填表”：仅填写并核对当前一笔的金额，选择题和剧情仍手动继续。正式版关闭 `dist/demo/test-tools.js` 的 `TEST_TOOLS`。八周规则、金额、旧档和验收见 [design/EIGHT_WEEKS.md](design/EIGHT_WEEKS.md)。

本轮更新：学前测验是独立的全屏必做入口，十道题全部提交后才加载经营开场。题目使用通用会计场景，不依赖柠檬茶摊的情节或数字；学前不公布分数或答案。经营结束后必须答完完全相同的十道题，再展示真实的学前 / 学后得分与逐题讲解。两次作答独立保存在本地，刷新可续答，未选答案不能进入下一题；“暂时不确定”是可选择的回答。测验进度与经营账目分开储存，旧游戏账目保留；新题库不沿用 v36 的旧答案。重新开张会同时重置本次两轮测验。

三张表保留简洁的专业名称。现金流量表列示“期初现金余额、现金流入、现金流出、期末现金余额”，支出按“购置存货、购置固定资产、支付费用、偿还借款本金”分项；实际向所有者分配后才增列该项。利润表主表为“营业收入、营业成本、毛利、费用、净利润”，费用明细可展开，含本篇已确认的损失；折旧在营业成本中计入一次。资产负债表保留“资产、负债、所有者权益”分栏，使用现金、存货、固定资产、应收 / 应付账款等名称。所有金额仍由原交易日志计算，格式升级归档旧草稿，不修改交易。

制作速度按客流规则模拟：每天至多六拨，最多四杯一拨，每拨愿等八分钟。旧设备每杯四分钟，新设备两分钟；客流与设备独立生成，原料不足另计，只有材料用完才能提前收摊。已经在营业中的旧存档保留原客流计划，下一天才采用新模型。此时间为教学用模拟参数。

## GitHub 与在线部署

源码仓库：https://github.com/huo70127/accounting-game

GitHub Pages 配置为从 `main` 分支的 `/docs` 目录发布。`dist/` 是可直接运行的游戏，`docs/` 由它生成；页面与素材使用相对路径，支持 GitHub 项目子目录。

## 从第一笔钱开始

- 大家走同一条故事和热身路线。先认识规范的专业名词和算法；按首次学习 / 复习区分提示，不把业务动作当新术语。点击后收起讲解，再用本局数字作答；选项按题目需要设置 2–6 个，借款题用“负债 / 营业收入”两项；可以主动查看提示，首次答案与提示使用分别记录。无论对错都讲解，错题反馈更醒目。毛利率进阶题选做。
- 想攒暑假看海的旅费，散步时发现大家都想喝冷茶，于是开个小摊。先算预算：二手桌子 10 元、压汁器 6 元、茶料 24 元、周转备用 4 元，共 44 元；自己的零花钱 12 元，向父母说明计划后借 32 元，免息，第八周末到期，提前清算则提前归还本金。
- 三张表不是开场就摆出来。第一次放钱后揭晓资产负债表及“资产＝负债＋所有者权益”；买设备时揭晓现金流量表；第一笔交货后揭晓利润表。每次揭晓有封面展开、用途说明和短提示音，确认后才进入表内填写。
- 第 1 周默认按配方采购可做 12 杯的材料，现款付清；柠檬、茶叶、糖浆、塑料杯、吸管可逐项调整。客人分别想买 2、4、6 杯，每杯售价 5 元、完整原料和包材成本 2 元，实际按材料能提供的数量成交。材料不足会少卖或未成交，未用完的材料继续按批次保留。第 2 周再按选择引入应收账款与应付账款；第五周再由共同经营引入股权。
- 打烊可以保留小摊：现金 64 元、设备 16 元、父母借款 32 元，净利润 36 元。资产 80＝负债 32＋所有者权益 48。普通打烊不出售桌子、不提前归还约定在结束经营时还的借款。
- 随时可二次确认后主动清算；新开张篇依次清茶料、卖设备、还借款。完整卖完后清算，设备回收 12 元、处置损失 4 元，净利润 32 元，还清借款后可分配现金 44 元，包含原投入 12 元；八周新路线会实际支付给所有者，摊位现金相应归零。
- 详细故事、揭晓顺序和试玩路线见 `design/OPENING_STORY.md`。v17 朋友入股与赊账路线仅用于继续旧档，说明见 `design/FROM_ZERO.md`。

## 报表原位教学

- 三张表与钱盒读同一份整数分交易流水。投入、借款、买设备、存货、营业收入、营业成本与清算损益各记一次。利润表按营业收入、营业成本、营业利润、营业外支出、利润总额、净利润的层次简化列示；毛利单独标为辅助计算。现金流量表按经营、投资、筹资分组，展开实际收款、付款、流入流出小计和净额，再核对期初至期末现金。
- 新成交先展示小票，由用户点击后打开报表；其他关键交易沿原流程。新行展开并标“新增”，旧行变动高亮。资产负债表从第一笔钱起就左右分栏：左边资产，右边所有者权益，借款出现后在右边加入负债；两侧合计始终在底部。手机也保持左右结构。表内使用紧凑金额空白；自动合计只读。未完成的页签与主入口用红色“待填”提示。
- 报表可以先关掉，回主页面看实际交易与金额；草稿、已查看页和错误次数保留，点击继续记账再回来。没完成练习不能推进交易，但不阻止查看事实。刷新不重复记账或重播已经看过的新行。
- 空白与 0 分开，最多两位小数。按报表行的含义保留符号：营业成本是正数扣减项目，投资活动现金流量净额可能为负数；输入时带负号或不带负号都兼容，支持普通 / Unicode 负号与括号负数；核对金额大小，离开空格或提交时按该行标准整理显示。没有 ± 按钮，输入符号不改变实际交易或报表方向。
- 点击“这一笔，记好了”先核对所有已填写金额；即使还有空白，填错的金额也当场定位，不等整笔填完才报错。已填正确、只是漏填时，切到下一处待填并温和提示，不报错、不计错误次数。只有已填但不正确的金额才在原行及底部提示；同一空格连续两次核对失败，展开本局实际数字的分步算法。修改不重绘输入框，不打断手机键盘。

## 形象、声音与界面

- 原批准的 2D / 3D 设计稿保留。默认静态表情使用这次的新图：小动物口鼻处自然收住，移除拟人的上扬微笑；补充算预算、筹钱、制茶、交易收钱、庆祝、打烊六组双人动作，按当前场景使用。其他已确认表情保留；每个取景区域单独裁剪，防止把表情上方的另一排角色带进来。资产说明见 `ASSET_CREDITS.md`。
- 改用奶油白底、深色文字和明亮的柠檬黄、蓝色、珊瑚红重点色；按钮、卡片增加层次与按压反馈。
- 主音量默认 82%；零钱声采用 CC0 真实硬币落入玻璃杯的短录音，声音设置保留落罐对照试听（见 `design/audio/COINS_CLINKS.md`）。通关声沿用已选 E 小型管弦乐庆祝句，单独播放增益降为原来的 55%，合成回退也同步降低。A 短音用于新报表 / 等式揭晓，F 仍保留备选。小摊菜单可以试听、调音量或静音。

- 三张表保持同一个固定尺寸浮层；标题、页签和操作区固定，中间通过上页 / 下页翻看，保持左右结构与标准金额列。底部提示、主按钮、次要操作各占固定区域，错误与漏填提示出现时也不挤动主按钮。主场景的继续按钮移到独立的固定底部操作栏，短内容、长剧情和选择题都在同一个位置。
- 静音、减少动画与键盘操作不影响流程。恢复旧存档不会补播庆祝音。

- 离开页面 / 切到后台保存并暂停，回来重新同步布局及空闲时钟，不自动补走时间或补播声音。声音仍由用户操作启动，补充触摸手势激活。

`platform-tests.mjs` 检查多种视口、虚拟键盘、缩放、弹窗兼容和草稿保留；`opening-dom-tests.mjs devices / fallback` 走完整开张篇，`clock` 另覆盖页面离开与返回。详细设备验收表见 `design/DEVICE_SUPPORT.md`。当前环境缺少 Sites 指定的 `cua_repl.js`，跳过浏览器预览；这些自动检查不等于微信、iPad 的真机验收。

## 一天的变化

场景上方有钟面、数字时间与已完成事件。筹备第一天经历想法、预算、零花钱和晚饭后的借款，第二天买桌子与茶料。开张后的空闲片段中，时钟自然向前走；客人在本局固定但事前不可见的时点出现，时钟随即暂停。读题、记账、弹窗和后台不走时，没有阅读倒计时。“让时间走快一点”可直接走过这段空闲，减少动画模式采用同一结果。

时间轴显示已完成事项和当前已触发的事件。客人实际到来后标记“客人来买茶 · 正在进行”，记账及相应教学期间继续保持当前状态；处理完后转为“卖出 X 杯茶”，同一事件不重复。未来客人、下一次结果及尚未发生的打烊继续隐藏。侧边记事保留已完成事项。刷新保留当前分钟与同一局的隐藏条件，重做从相同环境重新开始。`dist/demo/timeline.js` 统一提供时间、已完成记录与报表期间，`clock-runner.js` 只负责空闲时推进。时钟前进不自动成交、收款或记账。

格式、分类依据及本篇未模拟的项目见 `design/STATEMENTS_TIME_LAYOUT.md`。本篇采用小企业会计准则的主要列报层次，不把教学简表冒充完整法定报表；没有模拟所得税，净利润与利润总额相同。

## 清算与旧档

清算第一次点击只提醒，不改账。确认后保存检查点，分步或快速处理，再核对报表；可恢复到清算前。资产折价的差额计损失，债务不足偿还时保留，不自动抹去。结果停在清算后、向所有者分配前。

v16 / v17 旧档保留已发生的出资、股权、应收账款、应付账款、回款条件、金额草稿和随机环境；不改造成新故事。旧路线的成交概率 45% / 75% / 95%、回款概率 80% / 15% / 5% 与稳定事件种子照常使用，延期不重复确认营业收入。

# 柠檬茶小摊 · 第一章原型

广州街坊背景，孩子阿柠从零现金开始，向父母借 10 元启动，再花 8 元备好 4 杯手打柠檬茶的茶料。父母借款免息、开篇三天不要求归还，始终独立计入负债；第 2 天可借的 12 元短期贷款按原规则第 3 天还本付息。本版沿用三天原型，不包含后续章节、连锁或上市玩法。

纯 HTML / CSS / JavaScript，无需安装依赖。

启动：在项目目录运行 `python3 -m http.server 8080 --directory dist`，浏览器打开 http://localhost:8080 。请通过 HTTP 服务打开。

验证：`npm test`（账目与存档回归，以及界面/音频逻辑夹具测试）。

- dist/engine.js：交易流水、复式余额、阶段约束、报表、回退。
- dist/events.js：章节、商品和事件配置；后续可扩展商品。
- dist/app.js：交互与三页账本。
- dist/feedback.js / concepts.js：逐步出现的概念、交易增减、固定居中的手动关闭概念框。
- dist/storage.js：IndexedDB 自动存档、JSON 导入导出、版本与账目完整性检查。
- dist/style.css：手机响应式摊位。

每次成功操作后，完整交易、阶段、订单和第 2 天检查点一起自动保存到 IndexedDB。同一标签页保存期间锁住新的操作，防止重复记账。重新打开恢复进度，重玩也会保存。导入只接受当前存档版本，不会把坏文件覆盖到当前游戏。可通过导出下载 JSON 文件换设备或备份。

本地存档绑定当前浏览器与网站地址。清理网站数据会删除存档；没有跨设备自动同步，没有后端。首次存档以前的旧 demo 没有存储数据。

第三天只处理开门前的到期付款并结算。折旧在设备实际使用日收摊计提。团购款保留为第四天应收，不作为立即兑现来源。未实现未来章节的其他商品、连锁或资本市场功能。

## 晚客与现制茶报损

第一天先做好 4 杯现制茶。拒绝赊账后进入傍晚事件，玩家等待晚客出现，可能接到部分或全部需求，也可能无人购买。有需求时仍需逐杯交付、当场收款；晚间营业结束时，剩下的现制茶按每杯 2 元报损。随后供应商出售的是未制作茶料，可跨日留存，第二天按单现做。

晚客权重由 `events.js` 的 `EVENING_EVENT` 配置；`chance.js` 使用存档中的随机状态抽取。界面只呈现环境线索与风险，事件揭晓后才展示实际发生的交易。刷新、导入或重玩第 2 天不会重抽已经发生的晚客结果，重新开局会生成新的种子。旧版存档兼容读取，已完成的旧交易不会被追溯改写。

报损流水使用 `kind: 'spoilage'`：减少存货和利润，不影响现金。利润表单独列示报损，销售收入与已售成本仅从销售交易生成，避免把丢弃当作销售。现金与利润仍由同一份事实流水计算。

## 日内时间与短空档

`rhythm.js` 管理营业时钟、晴天/多云天气与可保存的等待进度。第一天从早上摆摊、第一位街坊、午间赊账选择，逐步过渡到傍晚和收摊；第二天散客按拨到来，午间较密、下午较疏。环境插曲一般约 1–4 秒，含多云加时也不超过 5 秒。真实等待仅在插曲内推进；当前订单与决策会等玩家操作，不会因为阅读缓慢丢失。

空档包含路人、云、擦台面动画，可叫卖一次，等待结束后自动进入下一拨客人；界面不提供快进。`street.js` 绘制时间、光线、天气、街景与递杯动画。收摊关灯并换上收摊字样，次日重新亮起。

等待剩余时间会自动保存。切出网页和打开账本时暂停，返回时不补算离线时间。旧存档可继续读取并按当前节点补上时间场景。若要体验完整的新节奏，可从头开局。


## 场景插曲与每日回顾

等待的短动画现在直接发生在摊位画面，使用轻遮罩、台面抹布、街坊经过和一句短字幕。叫卖按钮位于画面内，操作区只保留“暂无订单”，没有限时阅读段落。

新概念使用固定居中的原生模态框，解释概念并展示这笔交易在三张表中的增减，由大按钮手动关闭。营业时钟在阅读期间暂停。未读概念随交易一起保存，重新打开仍会出现。

第一、第二天收摊与第三天到期结算后，自动打开当天账本，展示结果摘要和三张报表。新概念若恰好在收摊产生（如折旧），并入同一账本，避免连续弹框。玩家主动合上账本才标记该日已回顾，才能进入下一天；回退会恢复对应检查点的回顾状态。常规营业中仍可随时手动打开账本。

## 关键条目记账练习

交易发生后，玩家看到一份已经列好部分条目的记账单，只补全 1–2 个关键条目的金额；条目名称和增减方向固定列好。借款重点填负债，备货重点填存货，首笔现销练收入与成本，赊销和收款练应收账款，设备/折旧/到期利息/还款练相应的新判断。熟悉的条目只读展示。同一营业日已经完成过的同类销售或备货自动沿用，不逐杯重复出题。

`journal.js` 根据同一份实际交易生成校验答案，允许交换行顺序，但不接受漏项、重复项目、方向或金额错误。错误不会修改交易或扣钱；第一次给检查提示，第二次解释原因，第三次提供对照讲解，仍由玩家修正金额空格。核对正确后，按大按钮才能继续，收摊交易先完成练习，再自动进入当日三表回顾。

草稿、错误次数、待完成题目和已完成的练习记录一起本地保存。记账或阅读讲解时营业时钟暂停；刷新也不能跳过未完成的题目。输入与系统事实分开保存，校验和继续都不会重复生成交易。

当前是“条目＋增减＋金额”的简化入门练习，没有引入正式借贷分录，也不代表已经覆盖完整的会计入门课程；后续章节可逐步增加账户判断、借贷规则与综合编报。


金额练习改用静态条目名称、固定增减标识和大号数字输入框，无下拉框。已填写条目直接显示金额，关键条目只留数字空格。旧版未完成练习会补齐名称与方向，保留已输入金额及错误次数。营业插曲结束自动接下一拨，去掉了手动快进按钮。

## 分原料采购与存货

`materials.js` 定义五类材料及教学配方：每杯柠檬 50 克、干白茶叶 3 克、白砂糖 15 克、杯子 1 个、吸管 1 根。示范单价分别为柠檬 10 元/斤（500 克）、白茶 10 元/50 克、糖 5 元/斤、杯子 0.20 元/个、吸管 0.05 元/根，合计每杯 2 元；水冰暂不单独计价。它们用于当前教学经济模型，不是市场行情或标准制作规范。

玩家可以分别购买五种材料，系统按最短缺材料计算可制作杯数。开篇目标是采购足够制作第一批 4 杯，其余材料保留；之后按订单现做。库存区与资产负债表中的存货明细显示原料、包材和现制茶，以及各批到期日。示范期限为柠檬 2 天、茶叶 30 天、糖 60 天；包材本章不设到期日，仍作为存货，使用时计入成本。

按批次、先到期先用。新营业日先处理原料到期报损，未使用包材继续留存；现制茶另按当天未售完报损。使用与销售只是不同存货形态的流转，购买不直接计为费用。历史收摊库存保留快照，查看往日报表时不会用今天的材料数量冒充昨天。

`currency.js` 以整数分汇总和对账，交易对外保持元，支持按克采购的小数金额与金额练习。`purchase-ui.js` 提供配方、数量加减、采购总额、瓶颈容量和库存明细。旧库存按原每杯 2 元配方迁移，保留既有账目。

## 第一张资产负债表

向父母借启动钱后，金额练习切换为左右分栏的简化资产负债表。纸张、现金条目、负债条目与会计原则按顺序缓缓出现；减少动态效果时直接显示。现金 10 元列在左边，右边“向父母借的钱”留一个金额空格，输入后实时对照两边合计。核对及手动继续规则不变。

教学原则完整写为“资产＝负债＋所有者权益”。本步没有自有投入或利润，权益为零，所以是 10＝10＋0；不会把“资产等于负债”当作通用规则。后续利润进入权益，收摊账本沿用同一左右布局，并保留上日末数值对照。

金额输入统一右对齐，去掉练习中的增减标识。其他交易练习仍填“本笔金额”，避免误解为期末余额。

## 直接在报表中填金额

记账练习现在打开与收摊账本相同的报表版式：资产负债表沿用左右分栏，利润表与现金流量表通过 `report-layout.js` 共同渲染。新条目在原表位置展开并标注“新增”，已有条目显示交易前数值与本次后的金额，关键空格就在对应行。

练习目标改为报表数值：资产负债表填交易后的当前余额，利润表填当天截至当前累计金额。收回应收款、还清短期贷款等场景可填 0。系统仍保存实际交易变动与已校验答案两份记录，不会因填写期末余额而重复记账。旧版练习迁移时保留交易和完成记录；若金额含义从变动额改为余额，则重置尚未完成的对应金额空格，错误次数保留。

同一笔交易影响两张表时，通过账本页签填写，系统会引导到尚缺金额的那张表；无需额外填写更多条目。首次借款只出现资产负债表，其他表按进度出现。新行的动画仅在本次练习首次打开相应页时播放，重试时不反复打断。

报表数字框使用普通文本输入、手机小数数字键盘和自定义校验，不显示上下微调按钮，金额右对齐。空白与 0 严格区分，允许最多两位小数。


## 轻交互与醒目的数字纠错

按钮增加短促的按压反馈。点击、材料落位、现金到账、答错、核对正确和每日完成使用共享 Web Audio 引擎的不同短音效，只在用户交互后启动；默认开启，可随时关闭，并在此浏览器保留声音偏好。静音、音频不受支持或标签页隐藏都不影响游戏流程。

报表提交错误后，错误金额框和对应条目高亮，金额框下给出空白、格式或金额不匹配的提示。核对按钮上方的固定区域说明哪里需要修改、为什么还不能继续，并提供“去修改”定位按钮。提交自动切到有错的报表并聚焦金额；修改不重绘输入框，不打断手机键盘，仍需主动重新核对。填对后显示绿色确认、短音阶和小彩纸动画，再由玩家手动继续。采购数量和钱盒不足也在采购单旁醒目提示。

减少动态效果与“跳过动画”会隐藏庆祝粒子；交互不会依赖声音或动画才能理解。没有新增扣分、限时答题或自动跳过反馈。

`ui-tests.mjs` 使用 DOM 与 AudioContext 夹具验证错误状态、跨表定位、修改后重新核对、成功门禁和静音行为；它不代替真实浏览器的布局、触屏及音频试听检查。
